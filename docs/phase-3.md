## 交叉确认失效边界

- 从未确认的对阵：不公开实际双方、局分或不一致的LIVE状态。
- 曾确认但未实际开始：确认失效后恢复名次占位，隐藏实际双方和比分。
- 真实开始/结束：保留开赛时冻结的实际双方、比分及状态，首页/赛程/详情标待复核；允许继续完成原场次。
- 管理员更改已提交小组结果，会推进小组成绩版本并使交叉/最终确认失效；任何正式单场结果变化均使最终确认失效。

新字段`Match.crossApprovalIdAtStart`记录合法开赛时的确认ID，关联原Approval；`startedAt`和非未开始状态共同作为真实开赛依据。不会依据一条被手工改成LIVE的状态猜测已获确认，不回填不存在的历史证据。开赛服务在同一事务中冻结双方及确认ID。

## 数据、事务与权限

只新增一条加列迁移`20261015000200_scoring_start_proof`，不扩展原自定义迁移器。其余字段复用阶段1模型：

| 记录 | 用途 |
| --- | --- |
| Credential | ADMIN或SCORER及场地、盐化散列、凭据版本。HttpOnly/SameSite=Strict加密会话只保存凭据ID及版本，每次受保护请求重新查库。 |
| Match / SetScore | 比赛版本、状态、实际双方、开赛和提交时间；逐局比分、人工确认、排除状态及原因。排除行不删除。 |
| ScoreAction | 全局唯一requestId、操作者、操作、预期/结果版本、规范请求及修改前后快照。逐分操作也有持久日志。 |
| AuditLog | 开赛、直接改分、结束局、整场提交、管理员更正、访问码重置日志；不记录明文访问码。 |
| Tournament / Approval | 正式成绩版本、小组成绩版本，以及失效后保留的发布确认历史。 |

记分事务先取得本赛事写锁，再校验身份、场地、请求幂等和比赛版本，一并保存比分、回执、日志及失效处理。Prisma/libSQL使用延迟事务，先执行不改变数值的写语句可避免两个连接读后升级写锁的竞争。只有数据库忙/事务竞争等有限错误会使用**同一请求和版本**最多重试两次；不自动给过期记分换版本。

相同操作者、比赛、请求号和请求内容重试返回同一应用版本及当前最新快照，不把旧回执快照覆盖新成绩。相同请求号换内容或身份拒绝。不同请求旧版本返回409及有权限读取的当前成绩；整场锁定返回423。两片场地没有额外互斥或队伍冲突检测。

POST检查本站Origin；本机按实际Host验证，正式反向代理部署应固定`FOUR_V_FOUR_SITE_ORIGIN`。输入严格校验且JSON体流式限制8KB。登录有单进程每分钟30次总量限制，适用于当前小型单赛事部署；没有新增Redis等基础设施。对公网部署仍需使用HTTPS。

本机待同步日志按凭据ID、比赛及请求号分别保存，两个标签页不会相互覆盖整个队列。网络错误不清日志；旧会话、损坏记录、并行标签页版本分叉及服务器冲突暂停核对。清理是操作者的明确选择，已经到达服务器的操作不会被这个选择撤销。浏览器清理站点数据会丢失尚未发送的本机记录。本阶段未加入离线网页缓存：完全断网时无法保证重新加载页面，联网重开后可恢复保留的队列。

## 写接口

均`Cache-Control: no-store, private`，受保护响应带`Vary: Cookie`。

| 方法和路径 | 内容 |
| --- | --- |
| POST `/api/manage/login` | `{accessCode}`，设置12小时会话；返回`actor:{id,version,role,courtId}`。 |
| GET `/api/manage/session` | 当前身份或null，不返回码或散列。 |
| POST `/api/manage/logout` | 销毁当前浏览器Cookie；保留本机未同步记录。 |
| GET `/api/scorer/matches` | 只返回当前身份有权读取的比赛快照。 |
| GET `/api/scorer/matches/[code]` | 读取有权限的单场及版本；跨场地403。 |
| POST `/api/scorer/matches/[code]` | `{requestId:UUID,expectedVersion,action}`。成功返回`{receipt:{requestId,appliedVersion,replayed},match}`。 |

`action.type`为`START`、`POINT`（setIndex/side/home或away/delta±1）、`SET_SCORE`（setIndex/homePoints/awayPoints）、`CONFIRM_SET`（setIndex）、`SUBMIT_MATCH`或仅管理员可用的`CORRECT_RESULT`（完整sets数组）。客户端不能提交身份、授权场地或自行指定正式版本。错误返回`error:{code,message}`，409/锁定等适当情况同时返回有权查看的最新match。

## 补充规则：单场地同时只允许一场进行中

根据用户后续实测反馈新增同场地开赛限制：记分员和管理员的START均在既有写事务锁内检查本场地其他LIVE记录，存在时返回409 `COURT_BUSY`，不改变目标比赛状态、版本、局分或操作回执。两台设备并发开始不同场次也只有一场成功。两片场地仍可各自进行一场，不检查跨场地队伍冲突。
